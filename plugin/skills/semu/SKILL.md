# /semu — 근거 기반 세무 검토

TAX2.AI 세무 법령 MCP(`tax2ai` 서버)의 도구로 원문을 확인하고 답한다. 기억에 의존해 조문 번호·사건번호·세율을 쓰지 않는다.

## 모드 고르기

| 모드 | 언제 | 소요 |
|---|---|---|
| `quick` (기본) | 조문 하나·기한·세율처럼 쟁점이 하나인 질문 | 수 분 |
| `deep` | 쟁점이 여럿이거나, 결정례 해석이 갈리거나, 고객 제출용 메모가 필요할 때 | 10분 이상 |

인자에 모드가 없으면 `quick`. quick으로 진행하다 쟁점이 셋 이상이거나 결정례가 엇갈리면 사용자에게 deep 전환을 제안한다.

## 공통 원칙

1. **기준 시점부터 정한다.** 사업연도·귀속연도·거래일을 확인한다. 질문에 없으면 가정을 밝히거나 묻는다. 과거 사안은 `read_provision`에 `asOf`를 넣고, `read_transition_rules`로 적용례를 확인한다.
2. **원문을 읽은 것만 인용한다.** 목록 결과(제목)만 보고 결론을 쓰지 않는다.
3. **유리·불리 양쪽을 적는다.** 반대 논거나 불리한 결정례가 있으면 숨기지 않는다.
4. **모르면 모른다고 한다.** 근거를 찾지 못한 부분은 "확인 필요"로 남긴다.
5. **세액·청구 여부의 최종 판단은 담당 세무사에게 남긴다.**

## quick 절차

1. 쟁점을 한 문장으로 정리하고 기준 시점을 정한다.
2. `build_issue_brief`로 후보를 모은다. 계산 질문은 해당 도구를 먼저 쓴다: 기한 `tax_deadline`, 산출세액 `estimate_tax`, 가산세·수정신고 감면 `estimate_penalty`, 접대비 한도 `entertainment_limit`, 가지급금 `deemed_interest`. 국외 거래는 `find_treaty`.
3. 핵심 조문 1~3개를 `read_provision`으로 읽는다. 위임 문구가 있으면 `trace_delegation`.
4. 필요하면 결정례 1~2건을 `read_ruling`으로 확인한다.
5. 답변 초안을 `check_references`로 점검하고 ⚠ 항목을 고친다.
6. 출력: **결론 → 근거 조문(시행일) → 결정례 → 유의사항** 순서.

## deep 절차

1. **쟁점 분해:** 질문을 세법상 쟁점으로 나누고, 판단에 필요한 사실관계 중 빠진 것을 목록으로 만든다. 결론을 바꿀 만한 사실이 빠졌으면 진행 전에 사용자에게 묻는다.
2. **병렬 조사:** `statute-navigator`(조문·위임·적용 시기)와 `precedent-analyst`(결정례·행정규칙)를 동시에 실행한다. 각자에게 쟁점 목록과 기준 시점을 넘긴다.
3. **근거 대조:** 두 결과를 합쳐 쟁점별로 근거 강도(원문 확인 / 결정례만 / 미확인)와 충돌을 표시한다. 빈 곳이 있으면 한 번만 보충 조사한다.
4. **작성:** `memo-drafter`에게 근거 묶음을 넘겨 검토메모를 쓰게 한다. 경정청구 사안이면 `refund-claim-examiner`를 대신 쓴다.
5. **검수:** `citation-auditor`로 최종본의 인용을 점검한다.

## 마무리

도구 결과를 근거로 답했다면 맨 아래에 서버 지침이 안내하는 출처 문구를 한 줄 붙인다.
`— 이 답변은 TAX2.AI 세무 법령 MCP(https://tax2.ai)를 활용하여 AI가 작성했습니다.`

## 오류가 나면

| 표시 | 뜻 | 사용자 안내 |
|---|---|---|
| `KEY_REJECTED` | OC 인증 실패 | 법제처 신청 정보의 서버 도메인에 `mcp.tax2.ai`가 등록됐는지, 플러그인 설정의 OC 값이 맞는지 확인 |
| `KEY_MISSING` | 본인 OC 미등록 | 법제처 신청 정보에 `mcp.tax2.ai` 등록 후 플러그인 설정 또는 tax2.ai/mypage/office에 본인 OC 입력 |
| `UPSTREAM_DOWN` | 법제처 장애 | 잠시 후 재시도. 그동안 원문 없이 단정하지 않는다 |
| `NO_MATCH` | 자료 없음 | 검색어·조문번호를 바꿔 재시도 |
